优化建议
🔴 删除成功不应使用"成功"类型
当前所有删除成功都用 uni.showToast({ title: "已删除", icon: "success" })，但删除是破坏性操作，用户可能误删。建议使用 info 类型而非 success，文案更中性，避免用户产生"删除是好事"的错觉。
重要 体验
🟡 表单验证提示应区分轻重
当前10处表单验证全用 icon: "none" 的 toast，一闪而过。对于关键验证（如"请输入体重"），建议用 warning 类型弹框让用户看清；对于次要提示（如"标签已存在"），可保留轻量 toast。
建议
🔴 删除确认和删除成功应形成闭环
当前 DeleteConfirm 组件确认删除后，又弹一个 toast "已删除"，体验割裂。建议：DeleteConfirm 确认后自带成功动画（已有），不再额外弹 toast。或者用 ResultModal 替代 toast，形成「确认→执行→反馈」完整链路。
重要 体验
🟡 TrainingCard 内嵌弹框应统一
TrainingCard.vue 已有自定义弹框实现（modal-overlay + modal-card），与新的 ResultModal 功能重叠。建议将 TrainingCard 的弹框也迁移到 ResultModal，保持全局一致性。
建议
🟡 uni.showModal 确认弹框需保留
record.vue 中体重重复记录用 uni.showModal 做确认，这类需要用户做选择的场景不适合用 ResultModal 替代。建议后续设计 ConfirmModal 组件，与 ResultModal 配合使用。
建议
🟢 网络错误提示应可操作
request.js 中的网络错误 toast 只有提示，没有重试按钮。建议 error 类型弹框的按钮文案改为"重试"，并支持回调函数，让用户可以直接重试失败的操作。
体验
🟢 记录成功后可增加激励文案
当前"记录成功"文案过于机械。建议根据记录类型和连续打卡天数动态生成激励文案，如"连续记录3天，继续加油！"、"本周第5次运动，超越80%的用户！"。
体验
🟢 更新成功应展示变更内容
当前"更新成功"没有告诉用户更新了什么。建议在 desc 中展示关键变更，如"体重从 65.2kg 更新为 64.8kg"，让用户确认操作结果。
