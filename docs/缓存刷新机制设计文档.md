# 缓存刷新机制设计文档

## 概述

本系统基于 Pinia + `pinia-plugin-persistedstate` 实现了**缓存优先 + 静默刷新**的数据加载策略，核心目标：

1. **快速响应**：优先展示缓存数据，用户无需等待网络请求
2. **数据新鲜**：后台静默刷新，成功后自动更新视图
3. **容错降级**：刷新失败时保留缓存数据，通过提示告知用户数据可能过期
4. **自动重试**：刷新失败后自动重试，提高弱网环境下的数据获取成功率

| 文件 | 职责 |

## 数据流程

### 首次加载（缓存未命中）

```
用户进入页面
  → loadWithCache(key, fetchFn)
  → 缓存未命中
  → 显示加载动画（SectionLoader loading=true）
  → 等待网络请求完成
  → 成功：写入缓存 + 渲染数据
  → 失败：有缓存则降级返回过期缓存，无缓存则抛出异常
```

### 再次加载（缓存命中）

```
用户进入页面
  → loadWithCache(key, fetchFn)
  → 缓存命中 → 立即返回缓存数据（loading=false，无等待）
  → 后台发起 silentRefresh（不阻塞用户）
  → 刷新成功：更新缓存 + 更新视图
  → 刷新失败：自动重试（最多2次，间隔3s）
  → 全部失败：显示提示（SectionLoader 黄色提示条 / uni.showToast）
```

## pageCache Store API

### 状态

```javascript
state: {
  // 统一缓存数据存储（支持任意 key）
  cacheData: {},

  // 缓存时间戳（用于判断过期）
  cacheTimestamps: {},

  // 刷新状态追踪
  refreshStatus: {},
}
```

> **设计说明**：缓存数据统一存储在 `cacheData` 对象中，而非顶层 state 属性。
> 这样任意 key 都能正常存取，不受 Pinia 预定义属性限制。
> 所有页面通过 `getCached(key)` / `setCache(key, data)` 访问，无需直接操作 `cacheData`。

### Getters

| Getter | 说明 | 返回值 |
|--------|------|--------|
| `isCacheValid(key, expiryMs)` | 判断缓存是否在有效期内 | `boolean` |
| `isRefreshing(key)` | 判断指定 key 是否正在刷新 | `boolean` |
| `getRefreshError(key)` | 获取指定 key 的刷新错误信息 | `string \| null` |

### Actions

#### `getCached(key)`

读取缓存数据，同时输出日志（命中/过期/数据年龄）。

```javascript
const cached = cache.getCached('weightTrend')
// 日志: [PageCache] ✅ 命中缓存: weightTrend | 数据年龄: 45s
// 日志: [PageCache] ❌ 缓存已过期或不存在: weightTrend
```

#### `setCache(key, data)`

写入缓存数据，同时记录时间戳。

```javascript
cache.setCache('weightTrend', weights)
// 日志: [PageCache] 💾 缓存已写入: weightTrend | 过期时间: 300s
```

#### `clearCache(key?)`

清除指定 key 的缓存，不传参则清除全部预定义缓存。

#### `silentRefresh(key, fetchFn, retryCount = 0)`

静默刷新核心方法，**不阻塞用户操作**。

**重试机制：**
- 最大重试次数：`MAX_RETRY = 2`
- 重试间隔：`RETRY_DELAY = 3000ms`
- 每次重试前设置 `refreshStatus` 为 `retry:N`
- 全部失败后设置 `refreshStatus` 为 `error:错误信息`

**状态流转：**

```
refreshing → success        （首次成功）
refreshing → retry:1 → success     （失败1次后重试成功）
refreshing → retry:1 → retry:2 → success   （失败2次后第3次成功）
refreshing → retry:1 → retry:2 → error:xxx  （全部失败）
refreshing → empty          （返回空数据）
```

**日志示例：**

```
[PageCache] 🔄 静默刷新开始: weightTrend
[PageCache] ❌ 静默刷新失败: weightTrend | 耗时: 5000ms | 错误: Network Error
[PageCache] 🔁 将在 3s 后重试: weightTrend (1/2)
[PageCache] ✅ 静默刷新成功: weightTrend | 耗时: 320ms
[PageCache] 💾 缓存已写入: weightTrend | 过期时间: 300s
```

#### `loadWithCache(key, fetchFn, options?)`

缓存优先加载，自动判断缓存命中/未命中。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `key` | string | - | 缓存 key |
| `fetchFn` | async function | - | 数据获取函数 |
| `options.forceRefresh` | boolean | `false` | 是否强制刷新（忽略缓存） |
| `options.expiryMs` | number | `300000` | 缓存过期时间（5分钟） |

## SectionLoader 组件

### Props

| Prop | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `loading` | Boolean | 必填 | 加载状态 |
| `cacheKey` | String | `''` | 缓存 key，用于日志关联 |
| `name` | String | `'rose-three'` | 加载动画名称 |
| `size` | Number | `180` | 动画尺寸 |
| `color` | String | `'#A855F7'` | 动画颜色 |
| `text` | String | `''` | 加载提示文字 |
| `minHeight` | String | `'300rpx'` | 加载区域最小高度 |

### Events

| Event | 说明 |
|-------|------|
| `refresh` | 用户点击黄色提示条时触发 |

### Methods

| Method | 说明 |
|--------|------|
| `showStaleHint()` | 显示黄色过时数据提示条（由页面在 `silentRefresh` 失败后调用） |

### 防抖逻辑

- 点击提示条后进入 3 秒防抖期
- 防抖期间：文字变为「正在刷新...」，图标变灰，禁止点击
- 加载完成（`loading` 从 true → false）时自动重置防抖
- 组件卸载时清理定时器

### 埋点日志

SectionLoader 在关键交互节点输出精确到毫秒的时间戳日志：

| 事件 | 日志格式 |
|------|---------|
| 提示条显示 | `[SectionLoader] ⚠️ 显示过时数据提示 \| 区域: xxx \| 显示时间: 2026-05-29 19:40:15.234` |
| 用户点击 | `[SectionLoader] 👆 用户点击刷新过时数据 \| 区域: xxx \| 点击时间: 2026-05-29 19:40:18.567 \| 防抖时长: 3000ms` |
| 防抖拦截 | `[SectionLoader] 🚫 防抖中，忽略重复点击 \| 区域: xxx \| 点击时间: 2026-05-29 19:40:19.123 \| 防抖剩余: 进行中` |
| 防抖结束 | `[SectionLoader] 🔓 防抖结束 \| 区域: xxx \| 结束时间: 2026-05-29 19:40:21.567` |

## 页面接入规范

### 使用 SectionLoader 的区域

```vue
<template>
  <SectionLoader
    ref="weightTrendLoader"
    :loading="weightTrendLoading"
    cache-key="weightTrend"
    name="rose-three"
    :size="160"
    color="#0EA5E9"
    text="正在加载体重数据..."
    min-height="400rpx"
    @refresh="fetchWeightTrend"
  >
    <!-- 内容 -->
  </SectionLoader>
</template>

<script>
async fetchWeightTrend() {
  const cache = usePageCacheStore()
  const cached = cache.getCached('weightTrend')
  if (cached) {
    this.weightTrend = cached
    this.weightTrendLoading = false
    cache.silentRefresh('weightTrend', async () => {
      const weights = await getWeightHistory()
      this.weightTrend = weights || []
      return this.weightTrend
    }).then(() => {
      if (cache.getRefreshError('weightTrend') && this.$refs.weightTrendLoader) {
        this.$refs.weightTrendLoader.showStaleHint()
      }
    })
    return
  }
  // ...首次加载逻辑
}
</script>
```

### 不使用 SectionLoader 的区域

```javascript
cache.silentRefresh('todayStats', async () => {
  const stats = await getTodayStats()
  this.todayStats = stats
  return stats
}).then(() => {
  if (cache.getRefreshError('todayStats')) {
    uni.showToast({ title: '统计数据可能已过期', icon: 'none', duration: 2000 })
  }
})
```

## 测试页面使用指南

路径：`/pages/test/cache-refresh`

### 验证步骤

1. **正常模式**：点击「运行测试」→ 数据加载成功，无提示条
2. **全部失败模式**：
   - 切换到「全部失败」
   - 点击「运行测试」→ 首次加载失败，无数据显示
   - 点击「清除缓存」→ 切换到「正常」→ 点击「运行测试」→ 数据加载成功
   - 切换到「全部失败」→ 点击「运行测试」→ 展示缓存数据 + 后台刷新失败（重试2次）→ 显示黄色提示条
3. **首次失败模式**：
   - 切换到「首次失败」→ 点击「运行测试」→ 展示缓存数据 + 后台第1次失败 → 自动重试第2次也失败 → 第3次成功 → 数据更新
4. **慢速模式**：
   - 切换到「慢速(3s)」→ 点击「运行测试」→ 展示缓存数据 + 3秒后刷新成功

## 常见问题排查

### Q: 用户看到数据但控制台报错 `[PageCache] ❌ 静默刷新失败`

**原因**：缓存命中展示了旧数据，但后台刷新失败。检查网络请求是否正常。

### Q: 黄色提示条一直显示

**原因**：静默刷新重试全部失败。检查：
1. 网络连接是否正常
2. 后端接口是否可用
3. 控制台日志中的错误信息

### Q: 数据看起来是旧的但没有提示

**原因**：可能是 `silentRefresh` 的 `.then()` 错误检测未接入。参考上方「页面接入规范」补全。

### Q: 缓存多久过期

**默认 5 分钟**（`DEFAULT_EXPIRY = 300000ms`）。过期后 `getCached` 返回 `null`，页面会走首次加载逻辑（显示加载动画）。
